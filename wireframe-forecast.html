Key design decisions made via Tree of Thought:
Q: What is the single source of truth for income?
Option A: Notion cashflow months (existing) — lags by a month, retrospective
Option B: Contracts database — forward-looking, drives strategy
Option C: Both, synced — complex, two sources of truth
→ Winner: B — Contracts drive forecasting. Actuals (Notion cashflow) validate it.
Q: How should scenarios be structured?
Option A: Manual input (user types revenue estimates) — error-prone, not connected
Option B: Probability sliders per pipeline contract — too complex
Option C: 3 pre-defined scenarios (all/50%/none of pipeline) + Custom toggle per deal
→ Winner: C — Simple tabs for 80% of use, custom toggle for precision.
Q: How should tax be shown?
Option A: Global tax settings → applied to all income — ignores BTW-exempt contracts
Option B: Per-contract BTW toggle → auto-calculated → quarterly totals shown
Option C: Separate tax module with manual inputs — complexity without benefit
→ Winner: B — BTW on/off per contract, rate in settings. Tax is derived, never entered manually.
Q: What is the primary metric to display?
Option A: Monthly revenue — raw, doesn't answer "am I ok?"
Option B: Cash balance — shows current state but not trajectory
Option C: Runway in weeks — directly answers "how long can I breathe?" (research consensus)
→ Winner: C — Runway is the hero. Everything else supports it.
Q: How to connect contracts to existing Notion cashflow months?
Option A: Replace cashflow months with contracts entirely — breaks existing data
Option B: Contracts feed the forecast projection; cashflow months remain for actuals
Option C: Contracts as overlay on existing system — two modes: actual (past) + contract (future)
→ Winner: B/C hybrid — Past months = actuals from Notion. Future months = derived from contracts. Clean split at today.
